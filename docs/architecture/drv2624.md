# DRV2624 programming guide

Source: repository [drv2624.pdf](../../drv2624.pdf), TI SLOS893D, August 2025,
particularly sections 7–8 and the application initialization notes. This is a
firmware reference; electrical, measurement-fixture and PCB specifications remain
in the datasheet. [drv2624.h](../../Massage_pen_FW/User/Inc/drv2624.h) owns all
register addresses, reset bytes, field masks, encodings, limits and conversion
formulas. Names below omit the `DRV2624_` prefix. Group register names such as
`CONTROL` are local labels; field names follow the datasheet.
[drv2624.c](../../Massage_pen_FW/User/Src/drv2624.c) implements nonblocking
register operations and retained status snapshots through the shared I2C engine.
See [vibration.md](vibration.md) for agreed motor requirements and generated
hardware references.

## Drive engine

The IC drives either an LRA or an ERM through differential PWM outputs.
`LRA_ERM` selects the actuator. Closed loop uses back-EMF to regulate actuator
motion and supply feedback to maintain strength while sufficient voltage
headroom remains. It adds startup overdrive and braking automatically. For an
LRA it also tracks resonance cycle by cycle and resynchronizes to an already
moving actuator. Resonance tracking does not itself require level calibration;
calibration establishes the strength scaling for the attached actuator.
`NG_THRESH` suppresses small requested outputs. Edge-rate control reduces output
switching interference; it has no documented software selector.

`CONTROL_LOOP` selects open or closed loop. Closed-loop positive amplitude means
requested drive; zero and negative amplitudes request braking. `RATED_VOLTAGE`
sets calibrated steady-state full scale, while `OD_CLAMP` bounds temporary
overshoot. Open-loop signed amplitude selects drive magnitude and polarity
(ERM rotation direction or LRA phase). `OD_CLAMP` supplies its full-scale
reference, and `RATED_VOLTAGE` is ignored. `OL_LRA_PERIOD_H/L` sets the commanded
LRA frequency; `LRA_WAVE_SHAPE` chooses square or sine drive in this mode.
`AUTO_BRK_OL` temporarily enters closed loop for automatic braking and requires
working closed-loop calibration.

`HYBRID_LOOP` selects hybrid rather than full closed-loop operation.
`INPUT_SLOPE_CHECK` can keep hybrid operation open loop unless the requested
transition is large enough; the datasheet gives no numeric slope threshold.
When LRA back-EMF is invalid, normal tracking can free-run using `DRIVE_TIME` and
`ZC_DET_TIME`, then resume tracking when back-EMF returns. Separately,
`LRA_AUTO_OPEN_LOOP` enables fallback after `AUTO_OL_CNT` failed synchronization
attempts, without resynchronization. That fallback always uses a square wave and
loses closed-loop overdrive/braking benefits.

## Processes and triggers

`MODE` selects RTP, RAM waveform sequencing, diagnostics or auto-calibration.
Selecting a process does not start it. Configure the process while idle, then
trigger it. Changing actuator type, mode, loop control, trigger function,
automatic braking controls or LRA waveform shape during execution aborts the
process and enters standby.

| `TRIG_PIN_FUNC` selection | Start / stop | Software control |
| --- | --- | --- |
| Pulse input | A pulse starts; a subsequent pulse cancels | `GO` also works |
| Level input | High starts/enables; low stops | `GO` writes cannot control playback |
| Interrupt output | Open-drain active-low event indication | `GO` is the trigger mechanism |

`GO` remains asserted while a process runs and clears when it finishes.
RTP holds `RTP_INPUT` continuously until stopped; the host can update it during
playback. RAM sequencing normally ends automatically. Diagnostics and fixed-time
calibration also finish automatically; infinite repeats and trigger-controlled
calibration require a stop request. A normal stop cancels diagnostics or
fixed-time calibration; trigger-controlled calibration instead takes final
measurements after that request.

The reset configuration is LRA, closed loop, RTP, external level trigger and
automatic braking into standby. The reset `RTP_INPUT` requests full positive
amplitude. Set the intended amplitude and trigger configuration before starting.
SimpleDrive uses an external trigger with compatible defaults; it does not
remove the need to validate those defaults for the actuator.

## Calibration and diagnostics

Before closed-loop use, calibrate the assembled actuator or restore results
validated for that actuator and input configuration. Set `LRA_ERM`,
`FB_BRAKE_FACTOR`, `LOOP_GAIN`, `RATED_VOLTAGE`, `OD_CLAMP` and `AUTO_CAL_TIME`.
For LRA also configure `DRIVE_TIME`, `SAMPLE_TIME`, `BLANKING_TIME`, `IDISS_TIME`
and `ZC_DET_TIME`. The drive-time guess should approximate the LRA half-period.
Current dissipation precedes blanking/settling, followed by zero-crossing and
back-EMF sampling. Excessively short/long timing can impair startup or stability.
Higher loop/braking gains trade faster response against stability; sample time
also affects back-EMF gain.

Select auto-calibration, trigger, let it complete, then capture `STATUS` and
check `DIAG_RESULT` and protection flags. Trigger-controlled calibration needs
at least `AUTO_CAL_TRIGGER_MIN_MS` before requesting completion; final
measurements need additional milliseconds. Successful calibration populates
`A_CAL_COMP`, `A_CAL_BEMF` and `BEMF_GAIN`. These compensate resistive loss and
back-EMF scaling; they are not vibration level controls. Save/restore all three
with the corresponding validated configuration, or recalibrate after reset.
Changes to rated voltage require recalibration. The
[vibration module](../../Massage_pen_FW/User/Src/vibration.c) calibrates on the
first nonzero request, retains results in RAM and restores them after driver
power loss. Reboot clears them; flash persistence remains deferred.

Diagnostics first measures resistance with a small current, then drives a test
waveform to verify actuator response. Convert `DIAG_Z_RESULT` using `CURRENT_K`
and the header formula. The resistance phase alone does not set `DIAG_RESULT`
and cannot detect output overcurrent using that small current. The functional
phase can fail for an open/short or invalid back-EMF. UVLO or overtemperature
can abort resistance measurement; critical faults can abort the functional
phase and assert failure. Do not treat an old result as a completed new test.
Without an actuator, closed-loop frequency/amplitude is not predictable; a
stationary resistive load does not demonstrate successful resonance tracking.

## RAM library and sequencing

The IC stores a customer-supplied waveform library, rather than a built-in
catalogue of named effects. `RAM_ADDR_H/L` sets the memory pointer. Each
`RAM_DATA` read or write increments that pointer; burst data streams through
the same port. Configure/load while idle and bounds-check the complete image.

The library begins with `RAM_LIBRARY_REVISION`, followed by header entries in
waveform ID order. Each entry contains start-address high byte, low byte and
configuration byte. The configuration packs `RAM_WAVEFORM_REPEATS` and
`RAM_EFFECT_SIZE`: size counts waveform data bytes and must be even and within
the header limits. Zero/odd sizes are malformed. Header IDs and data pointers
must stay inside the library; the entire header and data share the RAM capacity.

Waveform data interleaves signed amplitude and time bytes. `RAM_RAMP` occupies
the amplitude byte's high bit, leaving `RAM_AMPLITUDE` for the signed level.
With ramp clear, set that amplitude for the duration. With ramp set, interpolate
to the following point over the current duration; a ramp needs a following
point, and consecutive ramps are supported. Duration uses the physical tick
selected by `PLAYBACK_INTERVAL`. Use the documented signed range; no unsigned
format selection is defined. Include a suitable zero-amplitude tail if smooth
repetition is needed.

`WAV_FRM_SEQ1` through `WAV_FRM_SEQ8` hold effect IDs or waits. `WAITn` selects
which interpretation applies. A waveform terminator stops sequencing; otherwise
all populated slots run in order. Wait duration uses `SEQUENCE_WAIT_TICK_MS`,
independently of the RAM playback tick. `WAVn_SEQ_LOOP` repeats each slot;
`WAV_SEQ_MAIN_LOOP` repeats the whole sequence. Library-header repeats are a
third layer. An infinite inner repeat prevents later slots from being reached.
`DIG_MEM_GAIN` attenuates RAM effects and does not affect RTP.

`ODT`, `SPT`, `SNT` and `BRT` add signed time offsets to overdrive, positive
sustain, negative sustain and braking portions respectively, including ramps.
The waveform maximum positive and most negative levels identify overdrive and
braking. Overdrive/braking offsets apply only in open loop because closed loop
automates those functions. None of these offsets applies to RTP.

## Voltage limits and measurements

`OD_CLAMP` bounds overdrive and braking; it also scales open-loop playback.
`OD_CLAMP_TIME` can limit overshoot duration, after which
`RATED_VOLTAGE_CLAMP` limits output until a brake request. Braking receives its
own allowed overshoot period. The lowest applicable clamp takes priority, and
supply voltage always limits attainable output. The time clamp can take effect
away from a zero crossing and is ignored during calibration/diagnostics.

`BAT_LIFE_EXT_LVL_EN` enables one or both VDD thresholds. VDD sampled at the
start of an effect selects `OD_CLAMP_LVL1` or `OD_CLAMP_LVL2`. Order the thresholds
and clamps as described in the header. Battery clamps are ignored during
calibration/diagnostics; they are not a continuously updated battery estimator.

`VBAT` reports VDD during active waveform playback. It need not represent
battery voltage if the board supplies the IC from another rail. `LRA_PERIOD_H/L`
reports measured resonance; read high first and then low within the same
playback to obtain the locked pair. Averaging is controlled by
`LRA_PERIOD_AVG_DIS`; its history starts filled with zeros. Measurements while
idle or braking are not reliable resonance readings. Open-loop programmed and
closed-loop measured periods have different scales in the header.

Voltage formulas distinguish LRA RMS/peak and ERM average/clamp relationships.
Use physical timing values rather than selector codes. Future firmware must
use integer/fixed-point math with wide intermediates, explicit rounding,
nonzero period checks and valid square-root domains. No conversion functions
or chosen voltage settings are provided here.

## Status, power and communication caveats

`STATUS` flags are sticky and clear together on read. Capture one byte and
interpret that snapshot; repeated reads can erase evidence before another
consumer sees it. `INTZ_MASK` suppresses individual interrupt sources but does
not hide status. In interrupt mode TRIG/INTZ remains low until a status read
clears the latched interrupt. `DIAG_RESULT` is a result flag rather than a
separate interrupt source. `PROCESS_DONE` covers naturally completed sequencer,
diagnostics and calibration processes, not RTP or aborted processes.

UVLO, overtemperature and output overcurrent immediately stop a process and
bypass automatic braking. Flags remain sticky after the condition disappears;
clearing a flag does not remove its physical cause or resume the aborted
process. Output short detection occurs during a process, not while idle.
UVLO/temperature are additionally monitored during I²C activity in standby.
The datasheet recommends checking UVLO after transfers because a supply droop
can corrupt communication. Capture and retain that status rather than silently
consuming it in an unrelated read.

Standby preserves configuration and allows I²C. NRST low enters shutdown,
aborts playback and disables I²C; reset/power loss/brownout returns settings to
defaults. Reinitialize and reload the RAM library after reset; no nonvolatile
library retention is specified. Release NRST with valid power and observe
`POWER_UP_WAIT_MS` before I²C commands. Selecting `MODE` alone does not leave
standby: a trigger starts activity. The regulator output must not supply an
external load.

The normal address and optional shared broadcast address are separate header
constants. Reads set a byte register pointer, use a repeated start, and NACK
the last returned byte. Normal bursts increment register addresses; RAM bursts
increment the RAM pointer through `RAM_DATA`. Avoid undocumented gaps and
read-only fields, preserve reserved bits, and treat `GO` as an action/running
state rather than generic configuration. `CHIPID` and `REV` identify the device;
released silicon revisions need not all match the reset revision macro.
The automatic I²C watchdog recovers a stalled protocol; it is not a playback
watchdog and requires no software service.

Rev. D contains these operational caveats:

- With automatic standby braking and software triggers in interrupt-pin mode,
  stopping RTP or cancelling RAM playback early can leave pseudo-standby with
  extra current. After `AUTO_BRAKE_TICK_COUNT` physical playback ticks plus
  `AUTO_BRAKE_BUFFER_MS`, perform another I²C read or write to enter full standby.
- With automatic standby braking and external waveform triggers, return TRIG
  low within the braking period or later triggers may be missed. Respect
  `TRIGGER_PULSE_MIN_US`; new triggers during braking can be delayed/ignored,
  and a sufficiently fast start/stop can prevent playback from beginning.
- Automatic standby braking can cause repeated `PROCESS_DONE` events for
  multi-click/pattern effects. TI advises against using completion interrupts
  with that braking option enabled.
- The TRIG/INTZ pull-up interacts with its internal pull-down and increases
  current. TI recommends monitoring status over I²C for low-power use.

## Datasheet inconsistencies

Do not silently convert these into board settings or new APIs:

- The interrupt overview labels a narrower mask than the detailed table;
  the table omits the program-error row. Figure 7-6 establishes its mask bit,
  included in the header.
- The older open-loop frequency equation disagrees with the later period
  register definition. The header follows the later definition and the
  correction recorded in revision history.
- RAM prose repeatedly states one KiB, while Figure 7-14 depicts a larger end
  address. The header uses the stated capacity and does not assume extra RAM.
- Playback prose mentions unsigned formats and a mid-scale zero inconsistent
  with the explicit signed `RTP_INPUT` definition. No unsigned-format selector
  is documented. Use the signed register/data definitions; the RAM signed
  minimum follows the stated range rather than an inferred extra code.
- Ramp prose mentions only the slower tick after defining both intervals.
  Timing follows `PLAYBACK_INTERVAL`, as specified by the general RAM format.
- Initialization prose gives an incorrect location for `MODE` and suggests
  mode selection exits standby. Follow the register map and triggered-process
  behavior. NRST low is reset/shutdown, despite inconsistent use of “assert”
  in that initialization example.
- Calibration instructions contain narrower drive-time notation and example
  gains/durations that differ from reset defaults. Field widths/defaults in
  the header follow the register map; the examples are not a board profile.
- Alternate voltage clamps and battery thresholds lack independent conversion
  equations. The header identifies the matching code domains but flags any
  inferred scaling instead of claiming an independently specified formula.
